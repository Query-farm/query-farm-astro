<p class="api-section">Description</p>

<p>The aggregate_combine RPC&#39;s packed request — merges parallel-worker (or window segment-tree) partial state. MergeBatch&#39;s schema is always (source_group_id: int64, target_group_id: int64) : for each row, the accumulator state under source_group_id should be folded INTO the one under target_group_id . PROPERTY DECLARATION ORDER IS LOAD-BEARING — matches AggregateCombineRequestSchema exactly: function_name, execution_id, merge_batch, attach_opaque_data, schema_name.</p>

## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">enum</span> `VgiInitPhase`

<a class="api-source" href="https://github.com/Query-farm/vgi-csharp/blob/main/src/QueryFarm.Vgi/Protocol/VgiInitPhase.cs#L28" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>public enum VgiInitPhase</code></pre>

<p class="api-section">Description</p>

<p>Wire values: INPUT, FINALIZE, TABLE_BUFFERING, TABLE_BUFFERING_FINALIZE ( InitRequest.Phase ) — the C++ extension&#39;s phase_values array in BuildInitRequest ( vgi_rpc_types.cpp ). A dictionary-encoded ( dictionary(int16, utf8) ) field decodes via ValueCodec.ExtractEnum purely based on the incoming Arrow array&#39;s own type — declaring this field as a bare string? (as M1-M3 did, since phase was always null on the scalar/plain-table path) fails decode with &quot;Enum &#39;System.String&#39; has no member matching wire name ...&quot; the moment a real value ever rides the wire — see VgiOrderByDirection&#39;s doc comment for the same lesson learned earlier. Meaning: Input — table-in-out streaming exchange phase (ExchangeState-shaped): the client writes input batches, this replies with output batches. Finalize — table-in-out per-substream finalize (ProducerState-shaped, tick-driven), run on the SAME connection that just finished the Input phase. TableBuffering — table-buffering&#39;s Sink-phase init: mints/joins the query&#39;s execution_id on a fresh connection, which then immediately closes its (empty) input writer so the exchange completes; all real Sink traffic afterward is the standalone table_buffering_process / table_buffering_combine / table_buffering_destructor unary RPCs (each independently worker-pool-acquired — NOT guaranteed to land on this connection). TableBufferingFinalize — table-buffering&#39;s Source-phase init (ProducerState-shaped): carries InitRequest.FinalizeStateId , opened on whatever pooled connection the Source operator acquired for that one finalize_state_id .</p>
