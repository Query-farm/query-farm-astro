## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `ConstParamAttribute`

<pre class="api-sig"><code>[AttributeUsage(AttributeTargets.Parameter)] public sealed class ConstParamAttribute : Attribute</code></pre>

<p class="api-section">Description</p>

<p>Marks a Compute parameter as a bind-time constant argument — named after vgi-python&#39;s ConstParam marker. DuckDB requires the SQL call site to pass a foldable (constant) expression for this positional argument; its value is extracted once at bind and delivered to every batch of the call (never as a per-row column). ScalarFn resolves const parameters by a SEPARATE positional counter from ParamAttribute ones — the wire&#39;s positional_&lt;i&gt; struct fields inside BindRequest.Arguments are indexed 0.. over CONST parameters only, in Compute declaration order.</p>

<p class="api-section">Description</p>

<p>Marks a Compute parameter as a per-row (columnar) argument — named after vgi-python&#39;s Param marker ( Annotated[pa.Int64Array, Param(doc=...)] ), adapted for C#&#39;s attribute-on-parameter syntax. <a id="SecretAttribute"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `SecretAttribute`

<a class="api-source" href="https://github.com/Query-farm/vgi-csharp/blob/main/src/QueryFarm.Vgi/Attributes/SecretAttribute.cs#L20" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>[AttributeUsage(AttributeTargets.Parameter)] public sealed class SecretAttribute : Attribute</code></pre>

<p class="api-section">Description</p>

<p>Marks a Compute parameter as bound to a resolved DuckDB secret — named after vgi-python&#39;s Secret marker. Invisible in the function&#39;s SQL signature (not counted in IScalarFunction.ArgumentsSchema/ duckdb_functions() ); the C++ extension pre-resolves the secret (by SecretType, optionally narrowed by Name/ Scope) BEFORE the very first bind call and ships it in BindRequest.Secrets — the function must additionally declare this requirement in FunctionInfo.RequiredSecrets for the extension to bother resolving it at all (see Scalar.ScalarFn&#39;s ComputePlan , which derives that list automatically from every SecretAttribute it finds). The bound parameter type is IReadOnlyDictionary&lt;string, Apache.Arrow.IArrowArray&gt;? — the resolved secret&#39;s field name → single-element value column map (null when no matching secret was resolved). Since scalar functions only support STATIC secret declarations (no dynamic-scope two-phase retry — see Internal.SecretsAccessor&#39;s doc comment for why that&#39;s a table/table-in-out-only mechanism), the resolved value is available on the very first bind/compute call whenever a matching secret exists at all.</p>

<p class="api-section">Public members</p>

<div class="api-members">

<div class="api-member">

<pre class="api-sig"><code>public required string SecretType &#123; get; init; &#125;</code></pre>
<p>The DuckDB secret TYPE this parameter needs resolved (e.g. &quot;vgi_example&quot; ) — required, C++ enforces type matching.</p>

</div>

<div class="api-member">

<pre class="api-sig"><code>public string? Name &#123; get; init; &#125;</code></pre>
<p>Optional exact secret name for name-based resolution — null (the default) resolves by type (optionally narrowed by Scope) instead.</p>

<a id="TypeRules"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `TypeRules`

<a class="api-source" href="https://github.com/Query-farm/vgi-csharp/blob/main/src/QueryFarm.Vgi/Types/TypeRules.cs#L16" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>public static class TypeRules</code></pre>

<p class="api-section">Description</p>

<p>Numeric-promotion rules ported from vgi-java&#39;s farm.query.vgi.types.TypeRules (itself mirroring vgi-python&#39;s _promote_for_addition /common-type helpers) — used by any scalar fixture whose output type is derived dynamically from its (&quot;any&quot;-typed) input type(s) rather than declared statically ( double , add_values , sum_values ). The core idea in every rule below: promote for OVERFLOW HEADROOM, not just &quot;the wider of the inputs&quot; — doubling/adding two N-bit integers can overflow N bits, so the result gets the next tier up (capped at 64-bit); float always lands on float64; decimal gains exactly one more digit of precision (capped at Arrow&#39;s decimal128 38-digit ceiling).</p>

<p class="api-section">Public members</p>

<div class="api-members">

<div class="api-member">

<pre class="api-sig"><code>public static IArrowType CommonTypeForAddition(IArrowType a, IArrowType b) ;</code></pre>
<p>Common type of two operands for addition ( add_values(a, b) ): float wins outright; both-integer widens the WIDER operand one tier (capped at 64); decimal (or a mixed int/decimal pair) merges precision/scale via the DuckDB decimal-add rule, then adds two digits of headroom, capped at 38.</p>

</div>

<div class="api-member">

<p>Widest-of-N-operand promotion for varargs addition ( sum_values(...) ): scans left to right, floating wins immediately, otherwise keeps the widest integer seen, then applies PromoteForAddition to the final widest type.</p>
