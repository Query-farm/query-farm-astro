The first tutorial step: build a worker with one **scalar** function and call it from SQL — about
**10 minutes**, for first-time VGI users with Python 3.13+ and [uv](https://docs.astral.sh/uv/).

A scalar function maps one row to one row: `double(21)` → `42`.

What's going on:

1. **The `# /// script` header** is [inline script metadata](https://packaging.python.org/en/latest/specifications/inline-script-metadata/) — `uv run` provisions the dependencies, so there's no virtualenv to create.
2. **`Double.compute` receives a whole column** (`pa.Int64Array`) and returns a column of the same length. The `Annotated[…]` types *are* the schema — VGI derives the SQL signature from them.
3. **`CalcWorker` exposes a catalog** named `calc` containing the function.

<Callout type="tip" title="New to Apache Arrow?">
[Apache Arrow](https://arrow.apache.org/) is a language-independent **columnar** memory format.
Rather than rows of objects, data lives in **arrays** — also called **vectors**: a contiguous,
typed sequence of values for a single column (here, a column of 64-bit integers). VGI hands your
function a whole column as an Arrow array, not one value at a time, and operating on the whole array
at once is what keeps it fast — if you've written a DuckDB UDF before, this is the vectorized
equivalent.

In Python you work with these through **[PyArrow](https://arrow.apache.org/docs/python/)** (imported
as `pa`): `pa.Int64Array` is a column of `int64` values, and
[`pyarrow.compute`](https://arrow.apache.org/docs/python/compute.html) (`pc`) provides vectorized
operations like `pc.multiply` that run across the entire array. VGI moves these columns between
DuckDB and your worker as Arrow **record batches** — a chunk of a table, i.e. a set of equal-length
arrays.

<a href="https://arrow.apache.org/" target="_blank" rel="noopener" class="arrow-logo-link"><img src="/vgi/apache-arrow.svg" alt="Apache Arrow" class="arrow-logo" /></a>
</Callout>

## Step 2 — Attach and call it

Launch a DuckDB-compatible engine (Haybarn shown here), attach the worker, and call it:

<CodeBlock code={`ATTACH 'calc' (TYPE vgi, LOCATION 'uv run calc_scalar_worker.py');
SELECT calc.double(21);`} lang="sql" tryable={false} />

<QueryResult columns={["double(21)"]} rows={[[42]]} />

Over a real column:

<CodeBlock code={`SELECT calc.double(n) FROM (VALUES (1), (2), (3)) AS t(n);`} lang="sql" tryable={false} />

<QueryResult columns={["double(n)"]} rows={[[2], [4], [6]]} />

You've built and run your first VGI function. 🎉

<Callout type="tip" title="It didn't work?">
- **`Catalog Error: unknown type "vgi"`** — the extension isn't loaded. On stock DuckDB run
  `INSTALL vgi FROM community; LOAD vgi;` first; on Haybarn it's built in.
- **The `ATTACH` hangs** — run `uv run calc_scalar_worker.py` directly; the worker speaks Arrow over
  stdin/stdout, so it *looks* like it hangs waiting for input. You're checking for an import error
  on stderr.
- **`Binder Error: function not found`** — the SQL name is the snake_case of the class name
  (`Double` → `double`), qualified by the catalog name from `ATTACH`.
</Callout>
