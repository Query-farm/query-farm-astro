## vgi-client

The main CLI for invoking VGI functions and managing catalogs.

### Function invocation

<CodeBlock code={`vgi-client [OPTIONS]`} lang="bash" tryable={false} />

**Options:**

<table>
<thead>
<tr><th>Option</th><th>Description</th></tr>
</thead>
<tbody>
<tr><td><code>--input FILE</code></td><td>Input parquet file (omit for table functions)</td></tr>
<tr><td><code>--output FILE</code>, <code>-o</code></td><td>Output file (use <code>-</code> for stdout)</td></tr>
<tr><td><code>--format FORMAT</code>, <code>-f</code></td><td>Output format: <code>json</code> (default), <code>csv</code>, <code>parquet</code>, <code>arrow-ipc</code></td></tr>
<tr><td><code>--function NAME</code></td><td>Function name to invoke</td></tr>
<tr><td><code>--args JSON</code></td><td>Function arguments as JSON array (default: <code>[]</code>)</td></tr>
<tr><td><code>--named-arg KEY=VALUE</code></td><td>Named argument (repeatable)</td></tr>
<tr><td><code>--setting KEY=VALUE</code>, <code>-s</code></td><td>Function setting (repeatable)</td></tr>
<tr><td><code>--worker PATH</code>, <code>-w</code></td><td>Worker command (default: <code>vgi-fixture-worker</code>)</td></tr>
<tr><td><code>--type TYPE</code>, <code>-t</code></td><td>Function type: <code>auto</code>, <code>table</code>, <code>table-in-out</code>, <code>scalar</code></td></tr>
<tr><td><code>--projection-id N</code></td><td>Column IDs to project (repeatable)</td></tr>
<tr><td><code>--table-input-position N</code></td><td>Position (0-indexed) to insert table input in positional args</td></tr>
<tr><td><code>--max-workers N</code></td><td>Limit parallel workers</td></tr>
<tr><td><code>--worker-stderr</code></td><td>Show worker stderr output</td></tr>
</tbody>
</table>

### Examples

**Table function (generates data):**

<CodeBlock code={`# Generate a sequence of 100 integers
vgi-client --function sequence --args '[100]'

# Output as CSV
vgi-client --function sequence --args '[10]' --format csv`} lang="bash" tryable={false} />

**Table-in-out function (transforms data):**

<CodeBlock code={`# Echo input unchanged
vgi-client --input data.parquet --function echo

# Sum all numeric columns
vgi-client --input data.parquet --function sum_all_columns

# Repeat each row 3 times
vgi-client --input data.parquet --function repeat_inputs --args '[3]'`} lang="bash" tryable={false} />

**Scalar function (per-row transform):**

<CodeBlock code={`# Multiply values in column "price" by 2
vgi-client --input data.parquet --function multiply --args '["price", 2]' --type scalar`} lang="bash" tryable={false} />

**Output to file:**

<CodeBlock code={`vgi-client --function sequence --args '[1000]' --output result.parquet --format parquet`} lang="bash" tryable={false} />

## Catalog commands

Manage database catalogs exposed by VGI workers.

### Attach/detach pattern

Most catalog operations require an attach ID. Two workflows are supported:

**Explicit attach (recommended for stateful catalogs):**

<CodeBlock code={`# Attach and capture the attach ID
ATTACH_ID=$(vgi-client catalog attach mydb --worker ./worker.py | jq -r '.attach_opaque_data')

# Use attach ID for subsequent operations
vgi-client catalog schema list --attach-opaque-data $ATTACH_ID --worker ./worker.py

# Detach when done
vgi-client catalog detach $ATTACH_ID --worker ./worker.py`} lang="bash" tryable={false} />

**Auto-attach (for stateless catalogs):**

<CodeBlock code={`# Specify catalog name instead of attach ID
vgi-client catalog schema list --catalog mydb --worker ./worker.py`} lang="bash" tryable={false} />

### catalog list

List available catalogs from a worker.

<CodeBlock code={`vgi-client catalog list --worker ./worker.py`} lang="bash" tryable={false} />

### catalog attach

Attach to a catalog and get an attach ID.

<CodeBlock code={`vgi-client catalog attach <name> --worker <worker> [--options '{}']`} lang="bash" tryable={false} />

**Output:**

<CodeBlock code={`{
  "attach_opaque_data": "a1b2c3d4",
  "supports_transactions": true,
  "catalog_version": 1
}`} lang="json" tryable={false} />

### catalog detach

Detach from a catalog.

<CodeBlock code={`vgi-client catalog detach <attach_opaque_data> --worker <worker>`} lang="bash" tryable={false} />

### catalog create

Create a new catalog.

<CodeBlock code={`vgi-client catalog create <name> --worker <worker> \\
    [--on-conflict {error|ignore|replace}] \\
    [--options '{}']`} lang="bash" tryable={false} />

### catalog drop

Drop a catalog.

<CodeBlock code={`vgi-client catalog drop <name> --worker <worker>`} lang="bash" tryable={false} />

### catalog version

Get the current catalog version.

<CodeBlock code={`vgi-client catalog version --catalog <name> --worker <worker>`} lang="bash" tryable={false} />

## Schema commands

Manage schemas within a catalog.

### schema list

List all schemas in a catalog.

<CodeBlock code={`vgi-client catalog schema list --catalog <name> --worker <worker>`} lang="bash" tryable={false} />

### schema get

Get schema details.

<CodeBlock code={`vgi-client catalog schema get <schema_name> --catalog <name> --worker <worker>`} lang="bash" tryable={false} />

### schema create

Create a new schema.

<CodeBlock code={`vgi-client catalog schema create <schema_name> \\
    --catalog <name> --worker <worker> \\
    [--comment "Description"] \\
    [--tags '{"key": "value"}']`} lang="bash" tryable={false} />

### schema drop

Drop a schema.

<CodeBlock code={`vgi-client catalog schema drop <schema_name> \\
    --catalog <name> --worker <worker> \\
    [--ignore-not-found] [--cascade]`} lang="bash" tryable={false} />

### schema contents

List objects in a schema by type. Requires `--type` to select the object kind (`table`, `view`, `scalar_function`, `table_function`, or `aggregate_function`).

<CodeBlock code={`vgi-client catalog schema contents <schema_name> \\
    --catalog <name> --worker <worker> \\
    --type table`} lang="bash" tryable={false} />

## Transaction commands

Manage transactions for catalogs that support them.

### transaction begin

Begin a new transaction.

<CodeBlock code={`TX_ID=$(vgi-client catalog transaction begin \\
    --attach-opaque-data $ATTACH_ID --worker <worker> | jq -r '.transaction_opaque_data')`} lang="bash" tryable={false} />

### transaction commit

Commit a transaction.

<CodeBlock code={`vgi-client catalog transaction commit $TX_ID \\
    --attach-opaque-data $ATTACH_ID --worker <worker>`} lang="bash" tryable={false} />

### transaction rollback

Rollback a transaction.

<CodeBlock code={`vgi-client catalog transaction rollback $TX_ID \\
    --attach-opaque-data $ATTACH_ID --worker <worker>`} lang="bash" tryable={false} />

### Transaction example

<CodeBlock code={`# Attach to catalog
ATTACH_ID=$(vgi-client catalog attach mydb --worker ./worker.py | jq -r '.attach_opaque_data')

# Begin transaction
TX_ID=$(vgi-client catalog transaction begin \\
    --attach-opaque-data $ATTACH_ID --worker ./worker.py | jq -r '.transaction_opaque_data')

# Make changes within transaction
vgi-client catalog table create main users \\
    --attach-opaque-data $ATTACH_ID --transaction-opaque-data $TX_ID --worker ./worker.py \\
    --columns '[{"name":"id","type":"int64"}]'

# Commit or rollback
vgi-client catalog transaction commit $TX_ID \\
    --attach-opaque-data $ATTACH_ID --worker ./worker.py

# Detach
vgi-client catalog detach $ATTACH_ID --worker ./worker.py`} lang="bash" tryable={false} />

## vgi-serve

Serve any worker by module reference or file path — stdio by default, `--http` for cloud deployment.

<CodeBlock code={`# Stdio (default) — for subprocess/pipe use by vgi-client or DuckDB
vgi-serve my_worker.py
vgi-serve my_app.workers:ProductionWorker

# HTTP — for cloud deployment
vgi-serve my_worker.py --http
vgi-serve my_worker.py --http --host 0.0.0.0 --port 8080`} lang="bash" tryable={false} />

**Options:**

<table>
<thead>
<tr><th>Option</th><th>Description</th></tr>
</thead>
<tbody>
<tr><td><code>--http</code></td><td>Serve over HTTP instead of stdin/stdout</td></tr>
<tr><td><code>--host ADDR</code></td><td>HTTP bind address (default: <code>0.0.0.0</code>)</td></tr>
<tr><td><code>--port N</code>, <code>-p</code></td><td>HTTP port (default: <code>$PORT</code> or <code>8080</code>)</td></tr>
<tr><td><code>--prefix PREFIX</code></td><td>URL prefix for RPC endpoints</td></tr>
<tr><td><code>--cors-origins ORIGINS</code></td><td>Allowed CORS origins (default: <code>*</code>)</td></tr>
<tr><td><code>--describe</code> / <code>--no-describe</code></td><td>Enable description pages (worker + RPC API)</td></tr>
<tr><td><code>--max-stream-response-bytes N</code></td><td>HTTP-only producer-stream batch packing budget</td></tr>
<tr><td><code>--quiet</code>, <code>-q</code></td><td>Suppress the startup banner (stdio mode)</td></tr>
</tbody>

## Worker logging

All workers that use `Worker.main()` (including `vgi-fixture-worker`) and `vgi-serve` support
logging options on the command line. Logs are written to stderr.

### Options

<table>
<thead>
<tr><th>Option</th><th>Description</th></tr>
</thead>
<tbody>
<tr><td><code>--debug</code></td><td>Enable DEBUG level on all <code>vgi</code> and <code>vgi_rpc</code> loggers</td></tr>
<tr><td><code>--log-level LEVEL</code></td><td>Set log level: <code>DEBUG</code>, <code>INFO</code> (default), <code>WARNING</code>, <code>ERROR</code></td></tr>
<tr><td><code>--log-logger NAME</code></td><td>Target specific logger(s) instead of all defaults (repeatable)</td></tr>
<tr><td><code>--log-format FORMAT</code></td><td>Stderr format: <code>text</code> (default) or <code>json</code></td></tr>
<tr><td><code>--quiet</code> / <code>-q</code></td><td>Suppress the interactive-terminal startup warning</td></tr>
</tbody>
</table>

`--debug` overrides `--log-level` when both are provided.

### Examples

<CodeBlock code={`# Enable debug logging
vgi-fixture-worker --debug

# Set WARNING level only
vgi-fixture-worker --log-level WARNING

# Target a specific logger at DEBUG
vgi-fixture-worker --log-level DEBUG --log-logger vgi.worker

# JSON-formatted logs (for structured log pipelines)
vgi-fixture-worker --log-format json`} lang="bash" tryable={false} />

## Common patterns

### Piping data

<CodeBlock code={`# Generate data and process it
vgi-client --function sequence --args '[100]' --format parquet --output /tmp/data.parquet
vgi-client --input /tmp/data.parquet --function sum_all_columns`} lang="bash" tryable={false} />

### Using with jq

<CodeBlock code={`# Extract specific fields
vgi-client catalog attach mydb --worker ./worker.py | jq -r '.attach_opaque_data'

# Pretty print
vgi-client --function sequence --args '[3]' | jq .`} lang="bash" tryable={false} />

### Shell scripts

<CodeBlock code={`#!/bin/bash
WORKER="./my_worker.py"

# Attach
ATTACH_ID=$(vgi-client catalog attach mydb --worker $WORKER | jq -r '.attach_opaque_data')

# List schemas
vgi-client catalog schema list --attach-opaque-data $ATTACH_ID --worker $WORKER

# Cleanup
vgi-client catalog detach $ATTACH_ID --worker $WORKER`} lang="bash" tryable={false} />
