<a id="vgi.arguments.AnyArrow"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `AnyArrow`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/arguments.py#L317" target="_blank" rel="noopener">source</a>

<p class="api-section">Description</p>

Sentinel type for arguments accepting multiple Arrow types.

Use this with [`AnyArrowValue`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrowValue) in the Annotated pattern when an argument
should accept multiple valid Arrow types, validated via the ``type_bound``
parameter. When accessed, returns an [`AnyArrowValue`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrowValue) containing the value
plus metadata (position and name).

**Choosing Between Specific Types and AnyArrowValue**

- **Single required type**: Use ``Annotated[str, Arg(...)]`` or similar.
  The argument will only accept that exact type.

- **Multiple valid types**: Use ``Annotated[AnyArrowValue, Arg(...)]`` with
  ``type_bound`` to specify which types are acceptable. For example, numeric
  operations that work on integers, floats, and decimals should use [`AnyArrowValue`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrowValue).

The ``type_bound`` parameter is ONLY meaningful for [`AnyArrowValue`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrowValue) arguments.
Using it with other types will emit a warning.

Examples using Annotated (recommended):

<Code lang="python" code={`from typing import Annotated
from vgi import Arg, AnyArrowValue

# Single type: function only works with strings
class UpperCaseFunction(TableFunctionGenerator):
    column: Annotated[str, Arg(0, doc="String column to uppercase")]

# Multiple types: function works with any numeric type
class DoubleFunction(TableFunctionGenerator):
    column: Annotated[
        AnyArrowValue,
        Arg(0, type_bound=[pa.types.is_integer, pa.types.is_floating])
    ]

    def on_bind(self) -> None:
        # Access column metadata for dynamic output type
        self._output_type = self.column.value

# Any type: function works with all types
class IdentityFunction(TableFunctionGenerator):
    column: Annotated[AnyArrowValue, Arg(0, doc="Column to pass through")]`} />



**Accessing values**

When using [`AnyArrowValue`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrowValue), access the value via the ``.value`` attribute:


<Code lang="python" code={`val = self.column.value     # The column name as a string
pos = self.column.position  # The positional index`} />



**Note**

Unlike [`TableInput`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.TableInput), [`AnyArrow`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrow) arguments have actual Arrow values -
they are just not constrained to a specific Arrow type.

<a id="vgi.arguments.AnyArrowValue"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `AnyArrowValue`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/arguments.py#L281" target="_blank" rel="noopener">source</a>

<p class="api-section">Description</p>

Wrapper for [`AnyArrow`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrow) argument values with metadata.

When an [`Arg`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.Arg) returns an `AnyArrow` type, accessing the attribute returns
an [`AnyArrowValue`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.AnyArrowValue) instead of just the raw value. This provides access to
both the value and the argument's position/name for schema lookups.

Example using Annotated (recommended):

<Code lang="python" code={`from typing import Annotated

class MyFunction(TableFunctionGenerator):
    col1: Annotated[AnyArrowValue, Arg(0, doc="First column")]

    def on_bind(self) -> None:
        # self.col1 is an AnyArrowValue
        print(self.col1.value)     # The column name
        print(self.col1.position)  # The positional index`} />

Example using legacy Arg[AnyArrow] syntax:

<Code lang="python" code={`class MyFunction(TableFunctionGenerator):
    col1 = Arg[AnyArrow](0, doc="First column")  # type: ignore[assignment]`} />

<a id="vgi.arguments.Arg"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `Arg`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/arguments.py#L883" target="_blank" rel="noopener">source</a>

<p class="api-section">Description</p>

Descriptor for declarative argument parsing with optional validation.

Use as a class attribute to declare function arguments that are automatically
parsed from `self.arguments` when accessed. This eliminates the need to override
`__init__` for simple argument parsing.


**Note**

For named arguments (string position), the Python attribute name should
match the SQL key. This is the standard convention:


<Code lang="python" code={`format = Arg[str]("format")  # Recommended: attribute == key`} />

Avoid using different names:


<Code lang="python" code={`output_format = Arg[str]("format")  # Not recommended`} />

While this works at runtime, it can cause issues with metadata
serialization where only one name is preserved.

<a id="vgi.arguments.Arguments"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `Arguments`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/arguments.py#L382" target="_blank" rel="noopener">source</a>

<p class="api-section">Description</p>

Container for function arguments.

Access arguments using get() for Python values:


<Code lang="python" code={`# Positional arguments (by index)
count = args.get(0)                      # First argument
name = args.get(1, default="unnamed")    # With default

# Named arguments (by string)
separator = args.get("sep", default=",")
threshold = args.get("threshold")

# With type validation (optional, for strict checking)
count = args.get(0, type=pa.int64())`} />

For direct Arrow Scalar access, use positional/named attributes:


<Code lang="python" code={`scalar = args.positional[0]              # pa.Scalar | None
scalar = args.named["sep"]               # pa.Scalar`} />

#### <span class="api-icon api-icon--method"></span><span class="api-kind-tag api-kind-tag--method">method</span> `encoded_dict`

Convert arguments to a dictionary suitable for serialization.

Positional arguments are stored with keys "positional_0", "positional_1", etc.
Named arguments are stored with their actual names prefixed by "named_".

The reason why a dictionary is used is to facilitate serialization with Arrow,
which can easily handle flat structures, but doesn't handle variable typed
arrays of arbitrary objects.

<a id="vgi.arguments.Arguments.serialize_to_bytes"></a>
#### <span class="api-icon api-icon--method"></span><span class="api-kind-tag api-kind-tag--method">method</span> `serialize_to_bytes`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/arguments.py#L573" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>serialize_to_bytes() -&gt; bytes</code></pre>

Serialize [`Arguments`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.Arguments) to bytes using Arrow IPC format.

Sentinel type for table input parameters in table-in-out functions.

Use this as the type parameter for [`Arg`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.Arg) to declare which argument
receives the streaming table input. Every [`TableInOutFunction`](/vgi/docs/python/api/vgi-table_in_out_function/#vgi.table_in_out_function.TableInOutFunction) must have
exactly one [`TableInput`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.TableInput) argument, and it must be positional (not named).

The [`TableInput`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.TableInput) argument determines which table expression feeds the
function when called from SQL. It doesn't correspond to an actual Arrow
value - the table data arrives as streaming `RecordBatch`es via `process()`.

<a id="vgi.arguments.TaggedUnion"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `TaggedUnion`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/arguments.py#L213" target="_blank" rel="noopener">source</a>

<p class="api-section">Description</p>

A decoded union-typed argument: which member is set (``tag``) and its ``value``.

DuckDB ``UNION`` / Arrow union arguments are *tagged*: the discriminator
(which member is present) lives in the Arrow ``UnionScalar.type_code``, not
in the member value. Plain ``Scalar.as_py()`` returns only the member value
and drops that tag, so union arguments are decoded into this wrapper
instead — ``tag`` is the active member's field name and ``value`` is its
Python value.

Example:


<Code lang="python" code={`config: Annotated[TaggedUnion, Arg("config", arrow_type=pa.sparse_union([...]))]
...
cfg = params.args.config            # TaggedUnion(tag=..., value=...)
if cfg.tag == "random_forest_classifier":
    grid = cfg.value                # the member struct, as a dict`} />

Enforce const-argument value constraints at bind time.

Const arguments are bind-time scalars, so validate them once (not per batch /
per group). Reuses ``Arg._validate``, raising [`ArgumentValidationError`](/vgi/docs/python/api/vgi-arguments/#vgi.arguments.ArgumentValidationError)
for any value that violates a declared ``choices``/``ge``/``le``/``gt``/``lt``/
``pattern`` constraint — so a bad value fails fast at bind instead of silently
reaching ``compute()``/``update()``. Shared by the scalar and aggregate bind
paths so both enforce identically (and match the legacy descriptor path).
