<p class="api-module-doc__label">Module overview</p>

Base classes for table functions with cardinality hints and callback-based processing.

[`TableFunctionGenerator`](/vgi/docs/python/api/vgi-table_function/#vgi.table_function.TableFunctionGenerator) produces output batches via a per-tick callback. Each call
to `process()` either emits a batch via `out.emit()` or signals completion via `out.finish()`.

<a id="vgi.table_function.bind_fixed_schema"></a>
## <span class="api-icon api-icon--function"></span><span class="api-kind-tag api-kind-tag--function">function</span> `bind_fixed_schema`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/table_function.py#L1272" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>bind_fixed_schema() -&gt; type[T]</code></pre>

Class decorator to return FIXED_SCHEMA from on_bind for a [`TableFunctionGenerator`](/vgi/docs/python/api/vgi-table_function/#vgi.table_function.TableFunctionGenerator) subclass.

Sets ``cls._inline_bind_safe = True`` *only when* the decorator actually
installs its own ``on_bind``. The catalog framework reads this marker to
decide whether `Table(inline_bind=True)` is allowed — the contract is "the
decorator's bind is in control, output is exactly ``cls.FIXED_SCHEMA``,
no kwargs inspected." If the class already defined its own ``on_bind``,
the decorator silently leaves it alone and we *must not* set the marker;
otherwise the framework would inline a bind it doesn't actually control.

Subclasses inherit the marker via Python attribute lookup. A subclass
that overrides ``on_bind`` adds it to its own ``__dict__``; the catalog
framework's eligibility check is
``getattr(cls, "_inline_bind_safe", False) and "on_bind" not in cls.__dict__``,
which correctly excludes such subclasses.

<div class="api-meta-block"><p class="api-label">Returns</p><dl class="api-deflist"><dd>The same class, with an <code>on_bind</code> returning <code>cls.FIXED_SCHEMA</code> injected if it did not already define one.</dd></dl></div>

<a id="vgi.table_function.SecretsAccessor"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `SecretsAccessor`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/table_function.py#L129" target="_blank" rel="noopener">source</a>

<p class="api-section">Description</p>

Unified access to secrets — pre-resolved and dynamically requested.

Pre-resolved secrets (from Secret() annotations with static scope/name, or
unscoped lookups) are available immediately. Dynamic lookups (computed scope
from function arguments) register pending requests — the framework
automatically triggers a two-phase bind retry to resolve them.

<p class="api-section">Description</p>

Init-call phase for table functions.

``INPUT`` / ``FINALIZE`` drive the streaming [`TableInOutGenerator`](/vgi/docs/python/api/vgi-table_in_out_function/#vgi.table_in_out_function.TableInOutGenerator) path.
``TABLE_BUFFERING`` is the Sink+Source init phase for
[`TableBufferingFunction`](/vgi/docs/python/api/vgi-table_buffering_function/#vgi.table_buffering_function.TableBufferingFunction) — after init, traffic moves to
``table_buffering_process`` / ``_combine`` (unary) and
``TABLE_BUFFERING_FINALIZE`` opens a producer-mode finalize stream
per finalize_state_id.
