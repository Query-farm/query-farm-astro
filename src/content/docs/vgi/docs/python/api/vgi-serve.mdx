<p class="api-module-doc__label">Module overview</p>

Zero-boilerplate CLI for serving VGI workers.

Loads any [`Worker`](/vgi/docs/python/api/vgi-worker/#vgi.worker.Worker) by module reference and serves it — stdio by default
(matching vgi-rpc's ``run_server()``), ``--http`` for cloud deployment.

Usage:


<Code lang="python" code={`# Stdio (default) — for subprocess/pipe use by vgi-client or DuckDB
vgi-serve my_worker.py
vgi-serve my_app.workers:ProductionWorker

# HTTP — for cloud deployment
vgi-serve my_worker.py --http
vgi-serve my_worker.py --http --host 0.0.0.0 --port 8080`} />

Programmatic API:


<Code lang="python" code={`from vgi.serve import create_app, load_worker_class

app = create_app(load_worker_class("my_app:MyWorker"))
# Use with gunicorn: gunicorn app -w 4 -b 0.0.0.0:8080`} />

## <span class="api-icon api-icon--function"></span><span class="api-kind-tag api-kind-tag--function">function</span> `load_worker_class`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/serve.py#L58" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>load_worker_class(reference: str) -&gt; type[<a href="/vgi/docs/python/api/vgi-worker/#vgi.worker.Worker">Worker</a>]</code></pre>

Load a [`Worker`](/vgi/docs/python/api/vgi-worker/#vgi.worker.Worker) subclass from a module reference string.

Accepts several reference formats:

- ``module:ClassName`` — import *module* and return *ClassName*
- ``module`` — import *module* and auto-discover the single [`Worker`](/vgi/docs/python/api/vgi-worker/#vgi.worker.Worker) subclass
- ``./path/to/file.py`` or ``path.py`` — load from file path
- ``./path/to/file.py:ClassName`` — load from file path, return *ClassName*

Auto-discovery finds [`Worker`](/vgi/docs/python/api/vgi-worker/#vgi.worker.Worker) subclasses **defined** in the module (ignores
imported ones by checking ``__module__``).

<div class="api-meta-block"><p class="api-label">Returns</p><dl class="api-deflist"><dd>The <a href="/vgi/docs/python/api/vgi-worker/#vgi.worker.Worker"><code>Worker</code></a> subclass.</dd></dl></div>

<a id="vgi.serve.resolve_shared_signing_key"></a>
## <span class="api-icon api-icon--function"></span><span class="api-kind-tag api-kind-tag--function">function</span> `resolve_shared_signing_key`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/serve.py#L549" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>resolve_shared_signing_key(
    *,
    propagate_to_children: bool,
) -&gt; tuple[bytes, bool]</code></pre>

Resolve the signing key every process in this deployment must agree on.

The key seals HTTP state tokens and catalog opaque data. Every process
that might serve a continuation for a stream has to hold the *same* one:
a token sealed by one key fails the AEAD check under another, and the
failure is load-dependent rather than deterministic. A client whose
connection stays pinned to one process never notices; one that reconnects
mid-stream -- ``seek_to_token``, a load balancer, a respawned worker --
hits an intermittent 400 that looks like flakiness.

Resolution:

- ``VGI_SIGNING_KEY`` set: use it. Tokens survive restarts and are valid
  across every process configured with the same value. This is the only
  correct setting for a load-balanced or multi-instance deployment,
  because nothing here can reach a peer we did not start.
- Unset: mint a random key for this deployment. Tokens are then valid for
  the life of these processes and clients re-ATTACH after a restart.


<div class="api-meta-block"><p class="api-label">Parameters</p><dl class="api-deflist"><dt><code class="api-pname">propagate_to_children</code></dt><dd>True when this process will start worker processes that import the app themselves (a pre-fork server). A minted key is then exported to the environment so those children inherit it instead of each minting its own -- which is the bug this function exists to prevent.</dd></dl></div>

<div class="api-meta-block"><p class="api-label">Returns</p><dl class="api-deflist"><dd><code>(key, is_ephemeral)</code>. <code>is_ephemeral</code> is True when the key was minted here rather than configured, so callers can say so out loud.</dd></dl></div>

## <span class="api-icon api-icon--function"></span><span class="api-kind-tag api-kind-tag--function">function</span> `wsgi_app_factory`

<a class="api-source" href="https://github.com/Query-farm/vgi-python/blob/main/vgi/serve.py#L1140" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>wsgi_app_factory() -&gt; Any</code></pre>

Build the WSGI app from the environment — the pre-fork worker entry point.

Granian is pointed at ``vgi.serve:wsgi_app_factory`` and calls this once
per worker process. Everything it needs was published by
:func:`export_serve_config` in the parent, plus ``VGI_SIGNING_KEY``, which
the parent minted and exported so every worker seals state tokens with the
same key.

<div class="api-meta-block"><p class="api-label">Returns</p><dl class="api-deflist"><dd>The Falcon WSGI application.</dd></dl></div>
