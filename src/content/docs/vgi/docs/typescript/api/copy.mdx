<dt><code class="api-fname">close</code><code class="api-ftype">(params: CopyToCloseParams&lt;TArgs&gt;) =&gt; number | void | Promise&lt;number | void&gt;</code></dt>
<dd>

Write the destination and close it, once (called on the coordinator). Read
the shards persisted by `write` and perform the terminal write. Called even
for empty input. Return the row count (informational).

</dd>

<dt><code class="api-fname">description</code><code class="api-ftype">string</code><span class="api-fopt">optional</span></dt>

<dd>

COPY direction; only `"to"` is supported here.

</dd>

<dt><code class="api-fname">ordered</code><code class="api-ftype">boolean</code><span class="api-fopt">optional</span></dt>
<dd>

When true, the writer requires rows in source order — discovery advertises
`ordered=true` and the extension uses a single-threaded sink
(`REGULAR_COPY_TO_FILE`) so one worker receives every batch in source
order. Mirrors vgi-python's `Meta.sink_order_dependent`.

</dd>

<dt><code class="api-fname">options</code><code class="api-ftype">Record&lt;string, CopyToOption&gt;</code><span class="api-fopt">optional</span></dt>

COPY options, keyed by option name. The `file_path` is NOT an option.

<dt><code class="api-fname">tags</code><code class="api-ftype">Record&lt;string, string&gt;</code><span class="api-fopt">optional</span></dt>

<dt><code class="api-fname">examples</code><code class="api-ftype">FunctionExample[]</code><span class="api-fopt">optional</span></dt>

<dt><code class="api-fname">requiredSettings</code><code class="api-ftype">string[]</code><span class="api-fopt">optional</span></dt>

<dt><code class="api-fname">requiredSecrets</code><code class="api-ftype">string[]</code><span class="api-fopt">optional</span></dt>

<dd>

Optional secret-bind hook: forward CREATE SECRET credentials for
secret-backed cloud writes (S3/GCS/HTTP/…). Called during bind (only on the

## <span class="api-icon api-icon--function"></span><span class="api-kind-tag api-kind-tag--function">function</span> `defineCopyToFunction`

<a class="api-source" href="https://github.com/Query-farm/vgi-typescript/blob/main/src/functions/copy-to.ts#L170" target="_blank" rel="noopener">source</a>

<Code lang="ts" code={`export function defineCopyToFunction<TArgs = Record<string, unknown>>(
  config: CopyToFunctionConfig<TArgs>,
): TableBufferingVgiFunction`} />

<p class="api-section">Description</p>

Define a custom `COPY ... TO` format writer, returned as a
`TableBufferingVgiFunction` (kind `"table_buffering"`) carrying the
`copyToFormat` metadata marker. Register it in the catalog's function list
like any function; the catalog's `copyFromFormats()` introspection picks it
up and advertises the format (direction `"to"`). The worker's
`table_buffering_process` / `table_buffering_combine` RPCs drive write/close.

</div>
