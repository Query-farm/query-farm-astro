<a id="Codec"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">interface</span> `Codec`

<a class="api-source" href="https://github.com/Query-farm/vgi-typescript/blob/main/src/arrow/codec/registry.ts#L58" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>export interface Codec</code></pre>

<p class="api-section">Description</p>

Codec for a single Arrow type. Converts between the author-facing rich
representation and the internal canonical pivot. Both directions validate
and throw on invalid/lossy input. null/undefined pass through as null.

(Raw\<-\>canonical conversions are reserved for a later phase. When added they
belong here as `rawToCanonical` / `canonicalToRaw`.)

<p class="api-section">Fields</p>

<dl class="api-fields">

<dt><code class="api-fname">label</code><code class="api-ftype">string</code></dt>
<dd>

Human-readable type label, used in error messages.

</dd>

<dt><code class="api-fname">richToCanonical</code><code class="api-ftype">(value: unknown): unknown</code></dt>
<dd>

rich author value -\> canonical pivot.

</dd>

<dt><code class="api-fname">canonicalToRich</code><code class="api-ftype">(value: unknown): unknown</code></dt>
<dd>

canonical pivot -\> rich author value.

</dd>

<dt><code class="api-fname">rawToCanonical</code><code class="api-ftype">(value: unknown): unknown</code></dt>
<dd>

branded raw author value -\> canonical pivot. Largely identity on the
underlying number/bigint (raw === canonical for every type), but validates
and unbrands. Date32/Date64 raw values are plain day-number / ms-bigint,
so this differs from richToCanonical only in NOT accepting a JS Date.

</dd>

<dt><code class="api-fname">canonicalToRaw</code><code class="api-ftype">(value: unknown): unknown</code></dt>
<dd>

canonical pivot -\> branded raw author value. Validates and brands
(identity at runtime).

</dd>

</dl>

</div>
