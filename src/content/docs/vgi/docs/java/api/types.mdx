## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `CachedSchema`

<a class="api-source" href="https://github.com/Query-farm/vgi-java/blob/main/vgi/src/main/java/farm/query/vgi/types/CachedSchema.java#L19" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>public final class CachedSchema</code></pre>

<p class="api-section">Description</p>

Wire-portable IPC-encoded `Schema` with on-demand deserialisation
caching. Used by table-producer states that hold an output schema across
exchange ticks — the IPC bytes survive HTTP state-token round-trips
(Jackson serialises the public `#ipc` field), and the cached Schema
is reused per process to avoid re-decoding on every emit.

The class is intentionally a mutable POJO with a public no-arg
constructor so the `StateSerializer` reflection path can both
instantiate it and populate `ipc` from JSON.

<pre class="api-sig"><code>public final class ScalarHelpers</code></pre>

<p class="api-section">Description</p>

Helpers for scalar function processing: numeric dispatch + per-row mapping.

Phase 2 supports int64 and float64 dispatch with input-side widening from
smaller integer / float types. Wider numeric coverage (decimal, uint*, etc.)
arrives in later phases.

<a id="TypeRules"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">class</span> `TypeRules`

<a class="api-source" href="https://github.com/Query-farm/vgi-java/blob/main/vgi/src/main/java/farm/query/vgi/types/TypeRules.java#L15" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>public final class TypeRules</code></pre>

<p class="api-section">Description</p>

DuckDB-compatible numeric type promotion rules.

Mirrors `vgi-go vgi.PromoteForAddition`: scalar-arithmetic functions
promote integer inputs one width up (TINYINT → SMALLINT → INT → BIGINT) and
leave floats alone. Mixed int/float promotes to float.

<p class="api-section">Members</p>

<div class="api-members">

<div class="api-member">

<pre class="api-sig"><code>boolean isInteger(ArrowType t)</code></pre>

Tests whether `t` is an integer type (any width, signed or unsigned).

</div>
<div class="api-member">

<pre class="api-sig"><code>boolean isFloating(ArrowType t)</code></pre>

Tests whether `t` is a floating-point type (any precision).

</div>
<div class="api-member">

<pre class="api-sig"><code>boolean isNumeric(ArrowType t)</code></pre>

Tests whether `t` is numeric, i.e. integer or floating-point
(decimals are excluded; see `#isAddable`).

</div>
<div class="api-member">

<pre class="api-sig"><code>boolean isAddable(ArrowType t)</code></pre>

Tests whether `t` can participate in arithmetic addition — numeric
or decimal. Backs `TypeBoundPredicate.IS_ADDABLE` bind-time checks.

</div>
<div class="api-member">

<pre class="api-sig"><code>ArrowType promoteForAddition(ArrowType t)</code></pre>

Promote a single input type one width up (for `double(value)`-style
arithmetic). Floats stay; ints climb the tier.

</div>
<div class="api-member">

<pre class="api-sig"><code>String sqlTypeName(ArrowType t)</code></pre>

Render an Arrow type as the SQL name DuckDB users recognise
(e.g. `BIGINT`, `VARCHAR`, `DECIMAL(38,2)`). Falls back
to Arrow's `toString` for types without a clean SQL equivalent.

</div>
<div class="api-member">

<pre class="api-sig"><code>ArrowType commonTypeForAddition(ArrowType a, ArrowType b)</code></pre>

Promote two operands to a common arithmetic type (used by `add_values`).
Mirrors `vgi.CommonTypeForAddition` — float wins, otherwise the widest
integer width plus one tier (capped at int64).

</div>
