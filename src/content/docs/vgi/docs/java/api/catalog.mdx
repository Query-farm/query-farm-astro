<pre class="api-sig"><code>public record CatalogTable( String schema, String name, byte[] columns, String comment, Map&lt;String, String&gt; tags, String scanFunctionName, List&lt;Object&gt; scanFunctionPositional, Map&lt;String, Object&gt; scanFunctionNamed, Long cardinalityEstimate, Long cardinalityMax, boolean inlineCardinality, boolean inlineScanFunction, List&lt;List&lt;Integer&gt;&gt; primaryKey, List&lt;List&lt;Integer&gt;&gt; uniqueConstraints, List&lt;String&gt; checkConstraints, List&lt;ForeignKey&gt; foreignKeys, List&lt;ColumnStatistics&gt; statistics, List&lt;List&lt;String&gt;&gt; requiredFilters)</code></pre>

<p class="api-section">Description</p>

A catalog table. `columns` is the table's Arrow schema serialized
as IPC bytes. `scanFunctionName` (with `scanFunctionArgs`)
inlines the scan function so the C++ extension can skip
`catalog_table_scan_function_get`; if `null`, the worker
must implement that RPC manually.

## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">record</span> `ColumnStatistics`

<a class="api-source" href="https://github.com/Query-farm/vgi-java/blob/main/vgi/src/main/java/farm/query/vgi/catalog/ColumnStatistics.java#L30" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>public record ColumnStatistics( String columnName, ArrowType arrowType, Object min, Object max, boolean hasNull, boolean hasNotNull, Long distinctCount, Boolean containsUnicode, Long maxStringLength)</code></pre>

<p class="api-section">Description</p>

Per-column statistics returned by `catalog_table_column_statistics_get`
or `table_function_statistics`.

`arrowType` pins the sparse-union member type for `min`/`max`.
When both are `null` (column has no usable min/max), set `arrowType`
to `new ArrowType.Null()`.

`min` and `max` are boxed Java values matching `arrowType`:
`Long` for INT64, `Double` for FLOAT64, `String` for UTF8, etc.

<p class="api-section">Members</p>

<div class="api-members">

<div class="api-member">

<pre class="api-sig"><code>ColumnStatistics ofInt64(String name, long min, long max, boolean hasNull, Long distinctCount)</code></pre>

Statistics for an INT64 column.

</div>
<div class="api-member">

<pre class="api-sig"><code>ColumnStatistics ofFloat64(String name, double min, double max, boolean hasNull, Long distinctCount)</code></pre>

Statistics for a FLOAT64 column.

</div>
<div class="api-member">

<pre class="api-sig"><code>ColumnStatistics ofUtf8(String name, String min, String max, boolean hasNull, Long distinctCount, Boolean containsUnicode, Long maxStringLength)</code></pre>

Statistics for a UTF8 string column.

</div>
<div class="api-member">

<pre class="api-sig"><code>ColumnStatistics ofGeometry(String name, byte[] min, byte[] max, boolean hasNull, Long distinctCount)</code></pre>

Geometry-column stats: `min`/`max` are WKB-encoded corner-point
geometries (the spatial bounding box). Sent as plain `binary` on the
sparse-union wire — the C++ extension correlates `name` with the
table's `geoarrow.wkb`-typed column and rebuilds the spatial extent.

<pre class="api-sig"><code>public record Macro(String schema, String name, MacroType macroType, List&lt;String&gt; parameters, Map&lt;String, String&gt; parameterDefaults, Map&lt;String, String&gt; parameterDocs, String definition, String comment, Map&lt;String, String&gt; tags)</code></pre>

<p class="api-section">Description</p>

A SQL macro exposed in the catalog. `parameterDefaults` is an
optional ordered map of parameter-name → SQL expression (used when the
macro has named-with-default parameters). `parameterDocs` is an
optional parameter-name → description map: each documented parameter's
description flows over the wire via the macro `arguments_schema`'s
`vgi_doc` field metadata (the same channel functions use for
per-argument docs), so the DuckDB extension's `vgi_function_arguments()`
can surface it. Keys must appear in `parameters`.

<a id="ScanBranch"></a>
## <span class="api-icon api-icon--class"></span><span class="api-kind-tag api-kind-tag--class">record</span> `ScanBranch`

<a class="api-source" href="https://github.com/Query-farm/vgi-java/blob/main/vgi/src/main/java/farm/query/vgi/catalog/ScanBranch.java#L30" target="_blank" rel="noopener">source</a>

<pre class="api-sig"><code>public record ScanBranch( String functionName, List&lt;Object&gt; positional, Map&lt;String, Object&gt; named, String branchFilter, boolean writable, String sourceCatalog, String sourceSchema, String sourceTable)</code></pre>

<p class="api-section">Description</p>

One physical source backing a multi-branch VGI table. The C++ extension's
optimizer rewrites a multi-branch scan into `UNION_ALL` of one arm per
branch, binding each `functionName` against DuckDB's function catalog.
Mirrors vgi-python `ScanBranch`.

<p class="api-section">Members</p>

<div class="api-members">

<div class="api-member">

<pre class="api-sig"><code>ScanBranch</code></pre>

Validates the branch and defensively copies the argument collections,
normalizing `null` to empty. A branch is either a *function*
branch (`functionName` set) or a *catalog-table* branch
(`functionName` empty and `sourceTable` set — it scans
`sourceCatalog.sourceSchema.sourceTable` in a companion catalog).

</div>
<div class="api-member">

<pre class="api-sig"><code>ScanBranch of(String functionName, Object... positional)</code></pre>

Read-only branch with positional args and no filter.

</div>
<div class="api-member">

<pre class="api-sig"><code>ScanBranch filtered(String functionName, String branchFilter, Object... positional)</code></pre>

Read-only branch with positional args and a branch filter.

</div>
<div class="api-member">

<pre class="api-sig"><code>ScanBranch writable(String functionName, Object... positional)</code></pre>

Writable branch with positional args (the table's INSERT target).

</div>
<div class="api-member">

<pre class="api-sig"><code>ScanBranch catalogTable( String sourceCatalog, String sourceSchema, String sourceTable, String branchFilter)</code></pre>

Catalog-table branch (lakehouse federation): scans the base table
`sourceCatalog.sourceSchema.sourceTable` in a companion catalog
instead of calling a table function.

</div>
