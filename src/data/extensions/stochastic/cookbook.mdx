Recipes are organized by task and distribution family. Every univariate distribution exposes the same operations — `sample` / `samples`, `pdf` / `log_pdf` (and `pmf` for discrete ones), `cdf` / `log_cdf` / `cdf_complement`, `quantile`, plus property functions (`mean`, `variance`, `skewness`, …). Once you've used one family, the rest follow the same shape. Fitting and hypothesis tests are aggregates.

## Normal — the workhorse

Z-scores, confidence intervals, two-sided p-values, [VaR](https://en.wikipedia.org/wiki/Value_at_risk). The [Normal distribution](https://en.wikipedia.org/wiki/Normal_distribution) is parameterized by mean and standard deviation:

```sql
-- Quantiles, density, CDF
SELECT dist_normal_quantile(0.0, 1.0, 0.95)  AS p95;     -- 1.6449
SELECT dist_normal_pdf(0.0, 1.0, 0.5)        AS density;
SELECT dist_normal_cdf(0.0, 1.0, 1.96)       AS prob;    -- ~0.975
```

```sql
-- Z-score using property functions inline
SELECT
  height_cm,
  (height_cm - dist_normal_mean(100, 15))
   / dist_normal_stddev(100, 15) AS height_zscore
FROM observations;
```

```sql
-- Two-sided p-value from a Z-statistic
WITH z AS (SELECT 2.31 AS stat)
SELECT 2 * dist_normal_cdf_complement(0.0, 1.0, ABS(stat)) AS p_value
FROM z;
```

See [`dist_normal_pdf`](#dist_normal_pdf), [`dist_normal_cdf`](#dist_normal_cdf), [`dist_normal_quantile`](#dist_normal_quantile), [`dist_normal_sample`](#dist_normal_sample).

## Discrete counts — Binomial and Poisson

[Binomial](https://en.wikipedia.org/wiki/Binomial_distribution) for fixed-trial successes; [Poisson](https://en.wikipedia.org/wiki/Poisson_distribution) for events at a rate:

```sql
-- Binomial: P(X = 7), P(X ≤ 5), random k
SELECT dist_binomial_pdf(10, 0.3, 7)  AS prob_exactly_7;
SELECT dist_binomial_cdf(10, 0.3, 5)  AS prob_at_most_5;
SELECT dist_binomial_sample(10, 0.3)  AS k;
```

```sql
-- Poisson: probability of seeing >= 5 arrivals when λ=2.5
SELECT dist_poisson_cdf_complement(2.5, 4) AS prob_5_or_more;
```

```sql
-- Poisson sample for synthetic event-count columns
SELECT i, dist_poisson_sample(2.5) AS arrivals
FROM range(10) t(i);
```

See [`dist_binomial_pdf`](#dist_binomial_pdf), [`dist_binomial_cdf`](#dist_binomial_cdf), [`dist_poisson_cdf`](#dist_poisson_cdf), [`dist_poisson_sample`](#dist_poisson_sample).

## Time-to-event — Exponential, Weibull, Gamma

[Exponential](https://en.wikipedia.org/wiki/Exponential_distribution) for memoryless waiting times; [Weibull](https://en.wikipedia.org/wiki/Weibull_distribution) for time-to-failure with non-constant hazard; [Gamma](https://en.wikipedia.org/wiki/Gamma_distribution) for waiting times across multiple events:

```sql
-- Survival probability past t=2 for Exponential(rate=0.5)
SELECT dist_exponential_cdf_complement(0.5, 2.0) AS surviving;
```

```sql
-- Hazard rate at t=10 for Weibull(shape=1.5, scale=8)
SELECT dist_weibull_hazard(1.5, 8.0, 10.0) AS instantaneous_hazard;
```

```sql
-- Sample 1,000 service times from Gamma(2, 3)
SELECT dist_gamma_sample(2.0, 3.0) AS service_secs
FROM range(1000);
```

See [`dist_exponential_cdf_complement`](#dist_exponential_cdf_complement), [`dist_weibull_hazard`](#dist_weibull_hazard), [`dist_gamma_sample`](#dist_gamma_sample).

## Bayesian conjugates — Beta and Gamma priors

Closed-form [conjugate posteriors](https://en.wikipedia.org/wiki/Conjugate_prior) are one quantile call away. After observing 17 successes in 25 trials with a [Beta](https://en.wikipedia.org/wiki/Beta_distribution)(2, 2) prior, the posterior is Beta(19, 10):

```sql
-- Posterior mean and 95% credible interval
SELECT
  dist_beta_mean(19, 10)              AS posterior_mean,
  dist_beta_quantile(19, 10, 0.025)   AS ci_lo,
  dist_beta_quantile(19, 10, 0.975)   AS ci_hi;
```

See [`dist_beta_mean`](#dist_beta_mean), [`dist_beta_quantile`](#dist_beta_quantile).

## Fit a distribution, then test the fit

`dist_<name>_fit` estimates parameters from a column by maximum likelihood. Its fields are named like the distribution's parameters, so the fitted values feed straight into the other functions:

```sql
WITH durations AS (
  SELECT * FROM (VALUES (1.2), (0.7), (2.9), (1.8), (0.4), (3.6), (1.1), (2.2)) t(x)
), fit AS (
  SELECT dist_gamma_fit(x) AS f FROM durations
)
SELECT f.shape, f.scale,
       dist_gamma_quantile(f.shape, f.scale, 0.95) AS p95_duration,
       dist_gamma_ks_test(x, f.shape, f.scale).p_value AS ks_p_value
FROM durations, fit
GROUP BY f;
```

Fits and tests are ordinary aggregates, so they work per group:

```sql
SELECT region, dist_poisson_fit(orders).rate AS orders_per_day
FROM (VALUES ('north', 4), ('north', 6), ('north', 5), ('south', 9), ('south', 7), ('south', 11)) t(region, orders)
GROUP BY region
ORDER BY region;
```

See [`dist_gamma_fit`](#dist_gamma_fit), [`dist_gamma_ks_test`](#dist_gamma_ks_test), [`dist_poisson_fit`](#dist_poisson_fit).

## Hypothesis tests

The test aggregates compute the statistic and p-value from your rows:

```sql
-- Welch's t-test: did the treated group (1) differ from control (0)?
SELECT welch_t_test(x, grp) AS result
FROM (VALUES (5.1, 0), (4.8, 0), (5.6, 0), (5.0, 0), (6.2, 1), (5.9, 1), (7.1, 1), (6.4, 1)) t(x, grp);
```

```sql
-- One-sample t-test against a target mean of 5
SELECT one_sample_t_test(x, 5.0).p_value AS p_value
FROM (VALUES (5.1), (4.8), (5.6), (5.0), (5.4), (5.3)) t(x);
```

```sql
-- Chi-squared goodness of fit: expected values may be counts or proportions
SELECT chi_squared_test(observed, expected) AS result
FROM (VALUES (18, 0.2), (22, 0.2), (31, 0.3), (29, 0.3)) t(observed, expected);
```

```sql
-- Kolmogorov-Smirnov: do these values look standard normal?
SELECT dist_normal_ks_test(x, 0.0, 1.0) AS ks
FROM (VALUES (-1.2), (0.3), (0.8), (-0.4), (1.9), (0.1), (-0.7), (0.5)) t(x);
```

When you already have a statistic, the CDF complement gives the p-value directly:

```sql
-- Two-sided t-test p-value, df=29
WITH t AS (SELECT 2.045 AS stat, 29 AS df)
SELECT 2 * dist_students_t_cdf_complement(df, ABS(stat)) AS p_value
FROM t;
```

```sql
-- F-test (ANOVA) p-value, df1=3 df2=20
WITH f AS (SELECT 4.94 AS stat)
SELECT dist_fisher_f_cdf_complement(3, 20, stat) AS p_value
FROM f;
```

See [`welch_t_test`](#welch_t_test), [`one_sample_t_test`](#one_sample_t_test), [`chi_squared_test`](#chi_squared_test), [`dist_normal_ks_test`](#dist_normal_ks_test), [`dist_students_t_cdf_complement`](#dist_students_t_cdf_complement).

## Power analysis — the non-central family

The non-central distributions describe a test statistic when the null hypothesis is false, which is what power calculations need:

```sql
-- Power of a one-sided t-test (df=20) when the true effect gives a non-centrality of 2.5
SELECT dist_non_central_t_cdf_complement(20.0, 2.5, dist_students_t_quantile(20.0, 0.95)) AS power;
```

```sql
-- Power of an ANOVA F-test (df1=3, df2=20) at non-centrality 8
SELECT dist_non_central_f_cdf_complement(3.0, 20.0, 8.0, dist_fisher_f_quantile(3.0, 20.0, 0.95)) AS power;
```

See [`dist_non_central_t_cdf_complement`](#dist_non_central_t_cdf_complement), [`dist_non_central_f_cdf_complement`](#dist_non_central_f_cdf_complement).

## Heavy-tailed families — Pareto, Cauchy, Log-normal

Wealth, file sizes, internet traffic, financial returns. The tail dominates; reach for these when the Normal underestimates extremes:

```sql
-- Probability a file exceeds 1 GB under Pareto(scale=10MB, shape=1.5)
SELECT dist_pareto_cdf_complement(10.0, 1.5, 1024.0) AS prob_over_1gb;
```

```sql
-- Median income under Log-normal(meanlog=10.5, sdlog=0.7)
SELECT dist_lognormal_median(10.5, 0.7) AS median_income;
```

See [`dist_pareto_cdf_complement`](#dist_pareto_cdf_complement), [`dist_lognormal_median`](#dist_lognormal_median).

## Synthetic data — combine families per column

Sampling functions return one draw per call, so combine them with [`range()`](https://duckdb.org/docs/sql/functions/nested.html) over any source row count:

```sql
CREATE TABLE synthetic_users AS
SELECT
  i AS user_id,
  dist_normal_sample(170, 8)        AS height_cm,
  dist_lognormal_sample(10.5, 0.7)  AS annual_income,
  dist_poisson_sample(3.5)          AS sessions_last_week,
  dist_exponential_sample(0.1)      AS avg_session_minutes,
  dist_bernoulli_sample(0.12)       AS converted
FROM range(100000) t(i);
```

One query, 100k rows of realistic-looking fixture data — heights from a [Normal](https://en.wikipedia.org/wiki/Normal_distribution), incomes from a [Log-normal](https://en.wikipedia.org/wiki/Log-normal_distribution), session counts from a [Poisson](https://en.wikipedia.org/wiki/Poisson_distribution), conversions from a [Bernoulli](https://en.wikipedia.org/wiki/Bernoulli_distribution).

## Lists of samples

`_samples(params..., n)` returns `n` draws as one list, which suits per-row simulations:

```sql
-- 1,000 simulated daily demands per product, summarized per row
SELECT product,
       list_avg(d) AS mean_demand,
       list_max(d) AS worst_day
FROM (
  SELECT product, dist_poisson_samples(rate, 1000) AS d
  FROM (VALUES ('widget', 4.0), ('gadget', 12.5)) t(product, rate)
)
ORDER BY product;
```

## Multivariate — Dirichlet and multinomial

The [Dirichlet](https://en.wikipedia.org/wiki/Dirichlet_distribution) samples probability vectors and the [multinomial](https://en.wikipedia.org/wiki/Multinomial_distribution) samples category counts. Both take and return lists:

```sql
-- Random market shares around 20% / 30% / 50%
SELECT dist_dirichlet_sample([20.0, 30.0, 50.0]) AS shares;
```

```sql
-- 100 visitors split across three landing pages
SELECT dist_multinomial_sample(100, [0.2, 0.3, 0.5]) AS visits,
       dist_multinomial_pmf(10, [0.2, 0.3, 0.5], [2, 3, 5]) AS prob_of_2_3_5;
```

See [`dist_dirichlet_sample`](#dist_dirichlet_sample), [`dist_multinomial_sample`](#dist_multinomial_sample), [`dist_multinomial_pmf`](#dist_multinomial_pmf).

## Monte Carlo — the canonical example

```sql
-- Estimate π by sampling uniform points in [-1,1]² and counting hits inside the unit circle
WITH samples AS (
  SELECT dist_uniform_real_sample(-1.0, 1.0) AS x,
         dist_uniform_real_sample(-1.0, 1.0) AS y
  FROM range(1000000)
)
SELECT 4.0 * COUNT(*) FILTER (WHERE x*x + y*y <= 1) / COUNT(*) AS pi_estimate
FROM samples;
```

The same pattern — generate, filter, aggregate — handles VaR, payoff integration, queueing simulation, A/B-test power calculations.

## Value at Risk

```sql
-- 1-day 99% VaR assuming Normal returns
WITH params AS (SELECT 0.0001 AS mu, 0.02 AS sigma, 1000000 AS portfolio)
SELECT portfolio * (-dist_normal_quantile(mu, sigma, 0.01)) AS var_99
FROM params;
```

For heavy-tailed [VaR](https://en.wikipedia.org/wiki/Value_at_risk), swap [`dist_normal_quantile`](#dist_normal_quantile) for [`dist_students_t_quantile`](#dist_students_t_quantile) with a low `df`.

## Log-scale variants for likelihoods

Every PDF / CDF / CDF-complement has a `_log_*` variant. Use them inside likelihood computations and to avoid underflow on tiny tails:

```sql
-- Log-likelihood of one observation under N(0,1)
SELECT dist_normal_log_pdf(0.0, 1.0, 4.5) AS log_density;
```

```sql
-- Log-survival for very small tail probabilities
SELECT dist_normal_log_cdf_complement(0.0, 1.0, 6.0) AS log_tail;
```

See [`dist_normal_log_pdf`](#dist_normal_log_pdf), [`dist_normal_log_cdf_complement`](#dist_normal_log_cdf_complement).

## Reproducibility

Sampling uses DuckDB's per-connection random engine, so `setseed` makes the following samples reproducible — including in parallel:

```sql
SELECT setseed(0.42);
CREATE TABLE draws AS
SELECT i, dist_normal_sample(0, 1) AS z
FROM range(1000000) t(i);
```

Running the same pair again produces the same table. To share exactly the same draws across sessions or tools, keep the materialized table.
