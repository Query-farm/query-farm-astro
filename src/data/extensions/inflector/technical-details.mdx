## The one-call rename

The single most useful pattern: take a CSV or JSON file with `camelCase` headers and snake-case the entire result set in one statement, no per-column boilerplate:

```sql
SELECT *
FROM inflect('snake', (FROM read_csv('users.csv')));
-- firstName,lastName,emailAddress  →  first_name,last_name,email_address
```

[`inflect`](#inflect) is polymorphic on its second argument — pass it a `VARCHAR`, a `STRUCT`, or a parenthesized query. Same function name, three shapes:

```sql
-- 1. A single string
SELECT inflect('snake', 'helloWorld');                          -- 'hello_world'
```

```sql
-- 2. A struct — every key renamed, values untouched
SELECT inflect('snake', {'firstName':'John','lastName':'Doe'});
-- {'first_name': 'John', 'last_name': 'Doe'}
```

```sql
-- 3. A query result — every column header renamed
SELECT * FROM inflect('kebab', (FROM read_json('events.json')));
```

That's the headline feature. The rest of the surface is Rails / ActiveSupport-style scalar helpers for individual values.

<Callout type="warning" title="Pluralization is English-only">
[`inflector_to_plural`](#inflector_to_plural) and [`inflector_to_singular`](#inflector_to_singular) wrap the [`cruet`](https://crates.io/crates/cruet) Rust crate, whose ruleset and irregular-word table are English. They handle English irregulars such as `mouse` ↔ `mice`, `analysis` ↔ `analyses`, and `quiz` ↔ `quizzes`, but they have **no awareness of French, German, Spanish, or any other language**. Pass non-English input and you'll get a mechanical English-rule output, silently. For multilingual content, do inflection upstream and store the result.

The [v1.5 source fix `8628623`](https://github.com/Query-farm/inflector/commit/8628623) (extension version `2026100701`) adds the missing `people` → `person` and `children` → `child` rules, including compound suffixes (`salespeople` → `salesperson`, `grandchildren` → `grandchild`). These suffixes preserve lowercase, title case, and uppercase. The DuckDB 2.0 builds in the Query.Farm repository include the fix. Community build `ac9b69f` (DuckDB 1.5) leaves `people` and `children` unchanged; older installed binaries may still behave that way.

A handful of edge cases inside English are also worth knowing:

- **Modern uncountables** — `data`, `species`, `series` — round-trip irregularly.
- **Mechanical case tokenization** — [`inflector_to_snake_case('XMLHttpRequest')`](#inflector_to_snake_case) yields `xml_http_request`. Right for column work; to keep specific acronyms uppercase in PascalCase, camelCase, Title, Train and Sentence output, use the [`inflector_acronyms`](#acronyms) setting.
</Callout>

## Case formats supported

Every shape Rails / ActiveSupport ships, plus the obvious extras:

| Format | Example | To-function |
|---|---|---|
| `camelCase` | `helloWorld` | [`inflector_to_camel_case`](#inflector_to_camel_case) |
| `PascalCase` / `ClassCase` | `HelloWorld` | [`inflector_to_pascal_case`](#inflector_to_pascal_case) / [`inflector_to_class_case`](#inflector_to_class_case) |
| `snake_case` | `hello_world` | [`inflector_to_snake_case`](#inflector_to_snake_case) |
| `kebab-case` | `hello-world` | [`inflector_to_kebab_case`](#inflector_to_kebab_case) |
| `Train-Case` | `Hello-World` | [`inflector_to_train_case`](#inflector_to_train_case) |
| `SCREAMING_SNAKE_CASE` | `HELLO_WORLD` | [`inflector_to_screamingsnake_case`](#inflector_to_screamingsnake_case) |
| `Title Case` | `Hello World` | [`inflector_to_title_case`](#inflector_to_title_case) |
| `Sentence case` | `Hello world` | [`inflector_to_sentence_case`](#inflector_to_sentence_case) |

Each has a matching [`inflector_is_*`](#inflector_is_camel_case) predicate — useful when you need to *route* a value based on its current shape rather than blindly transform.

## Inflection helpers

Beyond pure case work:

- **Pluralize / singularize** — [`inflector_to_plural`](#inflector_to_plural), [`inflector_to_singular`](#inflector_to_singular).
- **Ordinalize** — [`inflector_ordinalize`](#inflector_ordinalize) (`1` → `1st`), [`inflector_deordinalize`](#inflector_deordinalize) (`1st` → `1`).
- **Foreign keys** — [`inflector_to_foreign_key`](#inflector_to_foreign_key) (`Message` → `message_id`).
- **Module paths** — [`inflector_demodulize`](#inflector_demodulize) (`ActiveRecord::CoreExtensions::String` → `String`), [`inflector_deconstantize`](#inflector_deconstantize) (`Net::HTTP` → `Net`).

- **Labels, slugs and class names** (DuckDB 2.0 build) — [`inflector_humanize`](#inflector_humanize) (`author_id` → `Author`), [`inflector_parameterize`](#inflector_parameterize) (`Crème Brûlée: A Recipe!` → `creme-brulee-a-recipe`), [`inflector_classify`](#inflector_classify) (`egg_and_hams` → `EggAndHam`).

These are direct ports of the corresponding [ActiveSupport::Inflector](https://api.rubyonrails.org/classes/ActiveSupport/Inflector.html) methods.

## Acronyms

The `inflector_acronyms` setting lists words that stay uppercase in PascalCase, camelCase (except the first word), Title Case, Train-Case and Sentence case output, and in the matching `inflector_is_*` predicates. Tokens are trimmed and uppercased; one-character tokens are ignored. snake_case, kebab-case and SCREAMING_SNAKE_CASE output are unaffected.

```sql
SET inflector_acronyms = ['HTML', 'API'];
SELECT inflector_to_pascal_case('html_api_parser') AS pascal,
       inflector_to_camel_case('parse_html') AS camel;
-- HTMLAPIParser, parseHTML
RESET inflector_acronyms;
```

In the DuckDB 2.0 build the setting is **session scoped**, like other DuckDB settings: `SET` affects only the current connection and `SET GLOBAL` sets the default for new ones. Value transforms read it when the query runs, so a prepared statement uses the value in effect when it is executed. Struct field names and `inflect(fmt, TABLE)` column names are part of the result type, so they use the value in effect when the query is planned. Earlier builds kept the list in a process-wide variable, so a `SET` in one connection changed results in every connection and every database in the process.

## Changes in the DuckDB 2.0 build

- **`inflector_acronyms` is per connection** (see [Acronyms](#acronyms)).
- **Colliding names are made unique.** When [`inflect`](#inflect) renames struct fields or query columns and two names become the same (`fooBar` and `foo_bar` both become `foo_bar`), later ones get `_1`, `_2`, … in column order, compared case-insensitively like DuckDB identifiers. Earlier builds returned duplicate column names, and the struct form could not build the struct. A name that inflects to an empty string (for example `___`) keeps its original name.
- **NULL options.** `inflect(fmt, TABLE, strip_accents := NULL)` and a NULL format in the table form now raise a clear error. The scalar forms return NULL for NULL arguments, as before.
- **Errors instead of crashes.** Input that is not valid UTF-8 or an internal failure in the Rust layer now raises an error, and strings containing NUL bytes are handled correctly.
- **New functions:** [`inflector_humanize`](#inflector_humanize), [`inflector_parameterize`](#inflector_parameterize), [`inflector_classify`](#inflector_classify).

```sql
SELECT * FROM inflect('snake', (SELECT 1 AS fooBar, 2 AS foo_bar));
-- columns: foo_bar, foo_bar_1
```

## Inflector vs RapidFuzz

Both extensions live in the **Matching & casing** group, but they answer different questions:

- **Use Inflector** when you know exactly what shape you want (`snake_case`, `kebab-case`, plural, foreign-key) and need to mechanically produce it. Single-input, deterministic output.
- **Use [`rapidfuzz`](/products/extensions/rapidfuzz)** when you have *two* strings and want a similarity score — record linkage, dedupe, spell-check. Fuzzy comparison, not transformation.
- **Both can coexist** — normalize naming with Inflector, then fuzzy-match across normalized values with RapidFuzz.
