These examples use DuckDB 2.0 or later. Complete the [repository setup and installation](#quick-install) first.

## Install and load

```sql
INSTALL webmacro FROM query_farm;
LOAD webmacro FROM query_farm;
```

The extension registers a single function: [`load_macro_from_url`](#load_macro_from_url). Everything below is a recipe around it.

## Load a macro from a Git repo

The recommended pattern — host the SQL in a Git repo, load by raw URL:

```sql
SELECT load_macro_from_url(
  'https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/search_posts.sql'
) AS res;
-- 'Successfully loaded macro: search_posts'

-- Now use it like any DuckDB macro
SELECT *
FROM search_posts('alice.example.com', text := 'quack');
```

The body of the URL must be exactly one [`CREATE MACRO`](https://duckdb.org/docs/sql/statements/create_macro) statement (scalar or table macro). See [`load_macro_from_url`](#load_macro_from_url) for the validation rules.

## Pin to an immutable commit

Use a commit SHA in the URL so a branch rebase or upstream change can't silently swap the macro out from under you:

```sql
SELECT load_macro_from_url(
  'https://raw.githubusercontent.com/Query-farm/sql-macros/'
  || 'a6a929d6d157bf10293dd04bffe606f8fabeda0d'
  || '/macros/search_posts.sql'
);
```

The commit SHA pins the SQL forever — the same URL today and a year from now returns the same bytes. This is the closest thing to a versioned macro release.

## Load several macros at once

A common bootstrap pattern at the top of a notebook or script:

```sql
SELECT
  url,
  load_macro_from_url(url) AS status
FROM (VALUES
  ('https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/search_posts.sql'),
  ('https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/normalize_handle.sql'),
  ('https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/active_users.sql')
) AS macros(url);
```

Any URL that fails the fetch or the statement check raises an error — the bootstrap halts, you find out at session start instead of at first use.

## Load from a private host with auth

On DuckDB 2.0, [`load_macro_from_url`](#load_macro_from_url) goes through DuckDB's HTTP stack, so an [HTTP secret](https://duckdb.org/docs/extensions/httpfs/https) scoped to the host adds its bearer token or headers to the request — handy for private repos:

```sql
CREATE SECRET macro_host (
  TYPE http,
  BEARER_TOKEN getenv('GITHUB_TOKEN'),
  SCOPE 'https://raw.githubusercontent.com/your-org/'
);

SELECT load_macro_from_url('https://raw.githubusercontent.com/your-org/private-macros/<sha>/macros/foo.sql');
```

On the Haybarn 1.5 build the request is a plain unauthenticated `GET`. There, the simplest pattern is a **presigned URL** — generate a short-lived signed URL upstream (S3, GCS, etc.) and load that:

```sql
SET VARIABLE macro_url = getenv('MACRO_PRESIGNED_URL');

SELECT load_macro_from_url(getvariable('macro_url'));
```

For an internally-routable host where TLS or network ACLs are the access control (e.g. `https://macros.your-org.internal/foo.sql`), a plain URL is fine.

## Use scalar and table macros

Either macro form loads the same way — the difference is how you call the result.

A **scalar macro** definition at [`normalize_handle.sql`](https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/normalize_handle.sql):

```sql
CREATE OR REPLACE MACRO normalize_handle(h)
AS lower(trim(trim(h), '@'));
```

A **table macro** at [`active_users.sql`](https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/active_users.sql), which carries its own sample rows:

```sql
CREATE OR REPLACE MACRO active_users(since_date) AS TABLE
SELECT user_id, last_seen
FROM (VALUES
    (1, DATE '2025-11-02'),
    (2, DATE '2026-02-15'),
    (3, DATE '2026-03-01')
) AS users(user_id, last_seen)
WHERE last_seen >= since_date
ORDER BY user_id;
```

After loading both, scalar macros go in the `SELECT` list; table macros go in the `FROM` clause:

```sql
SELECT load_macro_from_url('https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/normalize_handle.sql');
SELECT load_macro_from_url('https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/active_users.sql');

SELECT normalize_handle('@Alice  ') AS handle,
       u.last_seen
FROM active_users(DATE '2026-01-01') u;
```

## Replace a macro mid-session

`CREATE OR REPLACE MACRO` is the supported way to update a macro you've already loaded. If the URL's body uses `CREATE OR REPLACE MACRO`, re-loading swaps the definition in place:

```sql
-- Edit the SQL upstream, then re-run:
SELECT load_macro_from_url(
  'https://raw.githubusercontent.com/Query-farm/sql-macros/main/macros/search_posts.sql'
);
-- 'Successfully loaded macro: search_posts'  -- now the new definition
```

If the macro was created without `OR REPLACE`, you'll need to [`DROP MACRO`](https://duckdb.org/docs/sql/statements/drop) it first.

## Pair with `http_client` for richer pipelines

WebMacro is a one-trick extension on purpose — it loads macros and nothing else. For HTTP request patterns it doesn't cover (POST bodies, custom headers, reading non-macro JSON), pair with the [`http_client`](/products/extensions/http_client) extension, which exposes general-purpose `http_get` / `http_post` for SQL-level HTTP.

```sql
-- Fetch a macro index, then load each entry
INSTALL http_client FROM query_farm;
LOAD http_client FROM query_farm;

WITH index AS (
  SELECT (http_get('https://raw.githubusercontent.com/Query-farm/sql-macros/main/index.json')->>'body')::JSON AS j
)
SELECT load_macro_from_url(unnest(j->>'$.macros[*].url'))
FROM index;
```

## Drop a loaded macro

A loaded macro is just a regular DuckDB macro — drop it like any other:

```sql
DROP MACRO search_posts;
```

```sql
DROP MACRO IF EXISTS active_users;
```

See [`DROP MACRO`](https://duckdb.org/docs/sql/statements/drop) for the upstream syntax.
