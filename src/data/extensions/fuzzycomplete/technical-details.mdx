These examples use DuckDB 2.0 or later. Complete the [repository setup and installation](#quick-install) first.

## What changes the moment you load it

After registering the repository, install and load it in the DuckDB CLI:

```sql
INSTALL fuzzycomplete FROM query_farm;
LOAD fuzzycomplete FROM query_farm;
```

From there on, every Tab in the shell is fuzzy-matched. Type `usrs` and Tab, and `users` is the first suggestion. Type `gnst` against a table called `getNotificationStatus` — it appears at the top, because matches at camelCase word starts get a bonus. ATTACH a second database and Tab through `FROM ` — completions span both catalogs, properly qualified.

## How it ranks suggestions

Fuzzycomplete uses the Rust crate [`code-fuzzy-match`](https://crates.io/crates/code-fuzzy-match) — a port of the matcher Visual Studio Code uses for its command palette and Quick Open. The matching rules:

- **Ordered subsequence.** Every character of your query must appear in the candidate, in order. They don't have to be contiguous — `usr` matches `users` and `user_settings` but not `setUR`.
- **Word-boundary bonuses.** Characters that follow a separator (`_`, `.`) or sit at a camelCase boundary score higher. That's why `gNS` reliably picks `getNotificationStatus`.
- **Run bonuses.** Contiguous match runs score higher than scattered hits — `users` beats `u_e_r_s` for the query `usr`.
- **Tie-breakers.** Equal fuzzy scores break by relevance, then by fewer `_`/`.` separated parts, then lexicographically. Relevance (DuckDB 2.0, build `2026110701` and later): `SELECT`, then `FROM`/`INSERT`/`UPDATE`/`DELETE`, before other keywords; your own tables, views, catalogs and schemas before built-in ones; columns of the tables named anywhere in the statement before other columns; columns before functions. `suggestion_score` still reports only the fuzzy match, so the shell keeps listing equally good matches instead of picking one.
- **Comments.** Text inside `--` and `/* */` comments is skipped; inside an unterminated comment there are no suggestions. Block comments are recognised on DuckDB 2.0 from build `2026110701`.

## Replaces, not supplements, the built-in

DuckDB ships an [autocomplete extension](https://duckdb.org/docs/extensions/autocomplete.html) that uses edit-distance scoring. Both extensions register `sql_auto_complete`, which the CLI calls for Tab-completion. With the [v1.5 activation fix](https://github.com/Query-farm/fuzzycomplete/commit/8b89b19bbed0c7338a2a5e1dfc08eea88290e0ee), `LOAD fuzzycomplete FROM query_farm` replaces an already loaded stock provider. Run it after the CLI's startup loading, or in your `~/.duckdbrc`. If you explicitly load both providers, load `autocomplete` first; loading it for the first time after fuzzycomplete can fail with a duplicate-overload error.

## Update and verify completion

To replace a previously installed copy, run:

```sql
FORCE INSTALL fuzzycomplete FROM query_farm;
```

Then close and reopen the DuckDB CLI so it loads the new binary. Verify the installed build and the active matcher:

```sql
LOAD fuzzycomplete FROM query_farm;

SELECT extension_version
FROM duckdb_extensions()
WHERE extension_name = 'fuzzycomplete';

SELECT trim(suggestion) AS suggestion, suggestion_start
FROM sql_auto_complete('SLCT');
```

The second query should return exactly one row: `SELECT` with `suggestion_start = 0`. Build `9746833` leaves the stock provider active when it is already loaded, even though `LOAD fuzzycomplete` succeeds. If suggestions still look wrong after updating, check that `fuzzycomplete` is loaded after `autocomplete`, including in your `~/.duckdbrc`.

## Inspecting the matcher from SQL

Tab-completion in the CLI calls [`sql_auto_complete`](#sql_auto_complete) under the hood, but you can also query it directly — useful for sanity-checking ranking, for tests, or for scripts that want to surface suggestions:

```sql
SELECT trim(suggestion) AS suggestion
FROM sql_auto_complete('SELECT * FROM ord')
LIMIT 5;
```

The function returns rows ordered best-first. It walks the live catalog, so newly [`ATTACH`](https://duckdb.org/docs/sql/statements/attach)-ed databases and freshly created tables show up immediately — there's no separate index to refresh.

Each row has the same five columns as the stock extension, which the DuckDB shell reads by position:

| Column | Type | Meaning |
|---|---|---|
| `suggestion` | `VARCHAR` | The completion text. Keywords end in a space; catalog and schema names end in `.` |
| `suggestion_start` | `INTEGER` | Offset in the input where the completion replaces text |
| `suggestion_type` | `VARCHAR` | `keyword`, `catalog`, `schema`, `table`, `table_function`, `column`, `scalar_function`, `file_name` or `directory` |
| `suggestion_score` | `UBIGINT` | Distance from the best fuzzy match: `0` for the best, lower is better, equal scores are ties |
| `extra_char` | `VARCHAR` | The character the shell appends after accepting: a space after keywords, `.` after catalogs and schemas, the path separator after directories, a quote after file names |

The stock extension's named parameters are accepted too: `max_suggestion_count` caps the number of suggestions (default 20) and `max_file_suggestion_count` the number of file and directory suggestions, e.g. `sql_auto_complete('SELECT * FROM ', max_suggestion_count := 5)`. `max_exact_suggestion_count` is accepted but has no effect, since fuzzy matching has no exact-only tail.

### File names and the sandbox

Inside a string literal the completer lists the files in the directory you are typing (directories end in the path separator, files in a closing quote). It goes through DuckDB's file system, so with `SET enable_external_access = false` file and directory completion fails with a `Permission Error` (the shell then shows no suggestions); keyword, table and column completion keep working. On DuckDB 2.0 from build `2026110701`, file names that are not valid UTF-8 are skipped; earlier builds aborted the shell when Tab-completing in a directory that contained one.

## What's in the box

| Surface | Where it lives |
|---|---|
| Tab-completion in the CLI | Implicit — DuckDB's line editor calls `sql_auto_complete` on every Tab |
| [`sql_auto_complete(sql)`](#sql_auto_complete) | One table function; returns ranked suggestions for a partial SQL string |
| Configuration | None — install, load, done |

For SQL-level fuzzy primitives (similarity scores, distances, record linkage) load [`rapidfuzz`](/products/extensions/rapidfuzz). For prefix-tree lookups against large dictionaries, load [`marisa`](/products/extensions/marisa).
