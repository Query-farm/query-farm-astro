## What is Arrow Flight?

[Arrow Flight](https://arrow.apache.org/docs/format/Flight.html) is the standard wire protocol for moving Apache Arrow data over the network. It's built on gRPC and HTTP/2, uses the columnar Arrow IPC format end-to-end (no row/column transposition), and is supported across many languages and platforms — Python (PyArrow), Java, Go, Rust, C++.

Compared to ODBC/JDBC or REST APIs, Flight gives you:

- **Zero-copy columnar transport** — the bytes on the wire are already Arrow's columnar in-memory layout.
- **Native streaming** — large result sets stream lazily; the client doesn't buffer the whole thing.
- **Parallel data fetching** — endpoints can describe multiple data locations the client can pull from concurrently.
- **A standard RPC vocabulary** — `ListFlights`, `GetFlightInfo`, `DoGet`, `DoPut`, `DoExchange`, `DoAction`.

Airport implements the Flight client side inside DuckDB, so any Flight-aware backend becomes queryable from SQL.

## What can I connect to?

Anything that speaks Flight. Some practical examples:

- **Custom Python or Go services** that wrap proprietary data with `pyarrow.flight.FlightServerBase` or the Go `flight` package — Airport queries them directly.
- **Snowflake's Arrow Flight endpoints**, **Dremio**, **InfluxDB IOx**, **Microsoft Fabric**.
- **Internal data products** built on top of object storage where the Flight server handles authorization and Arrow conversion centrally.
- **Federation gateways** that expose multiple backend systems behind a single Flight URL.

If you can write a Flight server, Airport can query it as if it were a DuckDB catalog.

## How it integrates with DuckDB

- **`ATTACH ... (TYPE airport)`** — full catalog integration. Schema discovery, joins across local and remote tables, query pushdown where the server supports it, and INSERT/UPDATE/DELETE to writable backends.
- **Table functions** — `airport_flights`, `airport_take_flight`, `airport_action`, `airport_databases` for ad-hoc / streaming use without ATTACH.
- **Secret type `airport`** — managed credentials (`location`, `auth_token`, `criteria`) passed by name to all of the above.

## When should I use Airport?

- You want **SQL access to a service that already speaks Flight**.
- You're building a **federation layer** where DuckDB is the query engine over multiple backends.
- You want **streaming Arrow** between a producer and DuckDB without intermediate serialization (CSV/Parquet/JDBC).
- You need **mutation** against a remote system from inside SQL (DML statements through Flight's `DoPut`).

For one-off file reads (CSV/Parquet/JSON over HTTP or S3), use DuckDB's built-in readers — Flight is overkill there. Airport's value is the bidirectional, schema-rich, streaming RPC channel.
